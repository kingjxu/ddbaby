# 158 张 Hero 窗口全链路耗时

## 结论

本报告复用 158 张 Hero 审计的冻结窗口 `2026-10-10 13:58:00` 至 `14:46:43.999999 +08:00`。主指标严格按 `decision_cycle_id` 的第一条 `client_complete` 统计；重复 Hero 展示、decided 帧和其他玩家行动时间均不计入。

- 88 个 Hero 决策周期中，65 个产生首次展示，23 个无首次结果。成功周期的 `hero_turn_detected -> first_display` 平均 **2.888s**、P50 **2.863s**、P95 **3.338s**、最大 **4.448s**。
- **23/65（35.4%）超过3秒，1/65（1.5%）超过4秒**。这批扩大样本继续证实3秒体感存在。
- 最大耗时仍是服务端识别：平均 **1.958s**、P95 **2.394s**、最大 **2.647s**，约占首屏总耗时 **67.8%**；识别耗时与首屏总耗时相关系数为 **0.684**。
- 服务端之外的 HTTP/网络平均 **504ms**、P95 **804ms**、最大 **1.179s**，约占 **17.5%**，是第二大耗时。
- Hero 首次检测到 HTTP 开始平均 **351ms**、P95 **757ms**、最大 **931ms**。其中检测到采集平均213ms，采集到 HTTP 平均139ms；存在接近1秒的局部长尾，但不是平均2.9秒的主因。
- 服务端决策平均 **58ms**、P95 **75ms**；响应到首次展示平均 **15ms**。二者都不是整体瓶颈。
- 23 个无首次结果周期由 **11 个非法决策请求周期**和 **12 个识别不完整周期**组成。它们不混入成功耗时分位数，但属于比慢更严重的无结果体验。

平均首屏耗时可近似拆为：

`检测到HTTP 351ms + 服务端总耗时 2,018ms + 服务端外HTTP/网络 504ms + 响应展示 15ms = 2,888ms`

## 无结果周期与边界

- 11个非法决策请求周期包含20次请求，识别平均3.910s、P95 4.975s、最大5.327s；主要对应深色布局退化结果。
- 12个识别不完整周期包含46次请求，识别平均2.173s、P95 4.954s、最大6.422s。
- 65个成功周期包含138次可决策请求，但时延主指标每个周期只取一次首次展示，不把重复请求当作独立用户等待。
- 本报告只覆盖冻结窗口和已收到的1.0.27 trace，不能外推所有用户或所有桌型。

## 优先级

1. 先拆解并优化服务端识别内部阶段，目标把识别 P50 从2.012s降至1.2s以内、P95从2.394s降至1.8s以内。
2. 同时修复深色布局和识别不完整，验收必须同时看首次结果周期比例；只降低成功请求耗时不足以解决无结果。
3. 拆分并检查连接复用、建连/TLS/首字节，降低约0.5秒的服务端外HTTP开销。
4. 最后排查客户端检测到采集的0.6～0.9秒长尾；平均值不支持把它列为首要瓶颈。
